# Занятие №6 Bug Report
## Интернет-магазин: добавление товара в корзину

Студенты пройдут путь:
**Программа → тестирование → FAIL → Bug Report → доказательство воспроизводимости.**

---

### Как разобрать эту программу с группой
Здесь я бы не давал студентам сразу готовый Bug Report.

Сначала попросить их назвать:

1. Что является **Actual Result**?
2. Что должно происходить согласно требованиям — **Expected Result**?
3. Какие входные данные привели к ошибке?
4. Можно ли повторить ошибку?
5. Какие шаги нужно написать, чтобы другой человек смог повторить ошибку?

После этого вместе собрать отчет.

Например:

| Поле               | Содержание                                                |
| ------------------ | --------------------------------------------------------- |
| Summary            | Отрицательное количество товара позволяет создать покупку |
| Environment        | Windows 11, C++ Console Application                       |
| Preconditions      | Программа запущена                                        |
| Steps to Reproduce | Запустить → ввести -2 → подтвердить                       |
| Test Data          | -2                                                        |
| Expected Result    | Ошибка, покупка не создается                              |
| Actual Result      | Создается покупка с отрицательной стоимостью              |
| Reproducibility    | 100%                                                      |
| Evidence           | Скриншот консоли                                          |

Здесь особенно хорошо показать студентам разницу:

**Expected Result ≠ Actual Result**

Именно это различие превращает обычный результат теста в основу Bug Report.
---

## Рекомендованный формат работы на занятии
### 1. Совместная работа — программа №1

Студенты сначала просто тестируют программу.

После обнаружения ошибки преподаватель спрашивает:

**Что произошло?**

→ Actual Result

**А что должно было произойти?**

→ Expected Result

**Как воспроизвести ошибку?**

→ Steps to Reproduce

**С какими данными?**

→ Test Data

**Можно ли повторить?**

→ Reproducibility

**Как доказать проблему?**

→ Evidence

После этого вместе оформляется первый Bug Report.

---

### 2. Самостоятельная работа — программа №2

Здесь студент уже должен самостоятельно пройти весь цикл:

**Test → FAIL → Analysis → Bug Report**

---

### 3. Самостоятельная работа — программа №3

Усложнение за счет необходимости проверить несколько вариантов входных данных и найти дефект среди корректных сценариев.

---

### 4. Самостоятельная работа — программа №4

Фокус на том, чтобы студент не просто написал «промокод работает неправильно», а **точно описал воспроизводимый сценарий** и отделил Expected Result от Actual Result.

---

## Шаблон Bug Report для студентов

Можно дать им такой минимальный шаблон:

```text
BUG REPORT

Summary:
Краткое описание ошибки.

Description:
Что произошло и в чем проблема.

Environment:
ОС, версия программы, язык/платформа.

Preconditions:
Что должно быть выполнено до начала проверки.

Steps to Reproduce:
1.
2.
3.
4.

Test Data:
Какие данные использовались.

Expected Result:
Что программа должна была сделать.

Actual Result:
Что программа сделала фактически.

Reproducibility:
Всегда / Иногда / 3 из 5 раз / 100%.

Evidence:
Скриншот, видео или другой материал,
подтверждающий проблему.
```
